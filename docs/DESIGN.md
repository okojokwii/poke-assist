# poke-assist 設計

2026-10-22 の相談の内容をまとめたもの。まだ確かめていない前提は「未確認」と書いてある。

## 1. 目的と守る線

ポケモンチャンピオンズの対戦で、iPhone の画面を Mac から見て、相手の型の予想と
こちらの手の候補を出す。**操作は本人が行う**。

| 扱い | 内容 |
|---|---|
| しない | 自動で操作する BOT。BOT だと見抜かれないための工夫 |
| しない | 公式大会・オンライン大会での使用（対戦中の外部の助言は、大会のルールで禁じられているのが普通） |
| 守る | 出すのは「候補と理由」まで。決めるのは本人（言われた手を押すだけにしない） |
| 守る | 攻略サイトの内容を丸ごと自動で取り込まない（規約で禁じているサイトが多い）。読んで仕様をコードに起こす |

目標の見立て: アシストが効くのは、計算ミス・確認漏れ・型の読み違いを減らすこと。
上位を狙えるかは、本人の腕と試合数で決まる。判断の中心を探索エンジン（§5）にすると、
LLM だけで判断するより強くなる見込み。

## 2. 全体の流れ

```
iPhone ──(iPhone ミラーリング)──> Mac の画面
                                    │ 数秒ごとにスクショ（画面が変わった時だけ処理）
                                    ▼
                          画面の判定（選出／技選択／試合終了）
                                    │
                                    ▼
                    盤面の読み取り（文字認識・HP バーの測定。手元で処理）
                                    │ 盤面のテキスト
                    ┌───────────────┼────────────────┐
                    ▼               ▼                ▼
              ダメージ計算     探索エンジン       Claude（必要な時だけ）
              （確定数）     （数ターン先の計算）  （型の推定の補助・説明）
                    └───────────────┼────────────────┘
                                    ▼
                         助言の窓（候補3つ＋理由1行ずつ）
                                    │ 試合終了
                                    ▼
                        試合の記録（JSON）→ 集計 → 環境メモ
```

## 3. 画面の取得と盤面の読み取り

- 画面: macOS の iPhone ミラーリングのウィンドウを `screencapture` で撮る。
  iPhone はロック中で手元で使っていない時だけミラーリングできる（実機で人狼のアプリを
  確かめる作業とは同時にできない）。
- 画面の判定: 技のボタンが出た・選出の画面・結果の画面を、画像の一致で見分ける。
- 読み取りは **Claude に画像を渡さず、手元で行う**（画像は1枚で千〜数千トークンかかる）。
  - 技名・ポケモン名: macOS 標準の Vision フレームワークの文字認識
  - HP の割合: 決まった位置の HP バーの色を測る
- Claude には盤面の要約テキストだけを渡す。

## 4. ダメージ計算

- 図鑑の基礎データ（種族値・タイプ・特性・技・持ち物）は Pokémon Showdown のデータ
  （`@pkmn/dex` など）を下敷きにする。計算は `@smogon/calc` を参考にする。
- **未確認**: チャンピオンズのダメージ計算・ステータスの仕組みが本編と同じか。
  攻略サイト（ゲームウィズなど、チャンピオンズ対応のもの）を読んで違いを起こす。
  サイトに書いていない細部（端数の切り捨ての順番・乱数の幅・補正の掛け順）は本編の仕様で埋める。
- **検証**: 試合の記録で、実際に受けた・与えたダメージが計算の範囲に入っているかを
  自動で照らす。外れたら仕様のどこかが違う。

## 5. 探索エンジン（判断の中心）

ルールを人が書き並べるのではなく、計算で手を選ぶ。

1. シミュレータ: 「この盤面で、こちらが A・相手が B を選んだら次はどうなるか」を計算する
2. 探索: 手の組み合わせを数ターン先まで進め、盤面の有利さを点数にする
3. 同時に選ぶゲームなので、相手の手ごとの損得の表からナッシュ均衡を解き、手を確率つきで出す
   （いつも同じ手を選んで読まれる、を防ぐ）
4. 相手の型が見えない部分は、使用率と記録から「ありそうな型」を何通りか抜き出し、
   それぞれで計算して合わせる

- 手元で動くので Claude の利用枠を使わない。
- 参考: Pokémon Showdown 向けの探索型 BOT（Foul Play など）。
- LLM だけで判断すると中級者止まりになりやすい理由（このエンジンを置く理由）:
  同時手番の読み合いで手が単調になる／分岐を数えていない／勝敗は運の影響が大きく、
  数十試合では良い判断と運を見分けられない／上位の相手も対策を更新してくる。

## 6. Claude の使い方

| 場面 | モデル | 呼び方 |
|---|---|---|
| 毎ターン（読み合いの局面だけ。計算で決まる局面は呼ばない） | Haiku 5.5 | 自動 |
| 選出の画面 | Haiku 5.5（足りなければ Sonnet 5.5） | 自動・1試合1回 |
| 振り返り・環境メモの書き直し | Sonnet 5.5 | その日の終わりにまとめて1回 |
| 戦略の見直し | Opus 5.5 | 数十試合ごと、たまに |

- 呼び出しは `claude -p --model <モデル>`。API キーではなく Pro プランの枠で動く。
  自分専用の道具に留める（プランの認証を他のアプリや他人向けに組み込まない）。
- 試合中は `--input-format stream-json` で会話を開いたままにし、差分だけ渡す。
  会話は試合ごとに作り直す。モデルを切り替える時は盤面の要約をもう一方の会話へ渡す。
- 会話の記録が人狼の開発のものと並ばないよう、**このディレクトリで起動する**
  （記録は起動したディレクトリごとに分かれる）。`--no-session-persistence` が使えるかは
  作る時に `claude --help` で確かめる。
- 使ったトークン数は `--output-format json` の出力から1試合ごとに記録する。

### 利用枠の見積もり（Pro）

上限はトークン数で公開されていないので目安だけ。1日10試合で、全部を毎ターン呼ぶと
Haiku 約60万＋Sonnet 約30万トークン。Pro では無視できない量なので、上の表のとおり
「呼ぶ局面を絞る・振り返りはまとめて」で減らす。探索エンジンができれば大きく減る。
実際の量は記録を見て直す。

## 7. データ

| データ | 中身 | 出どころ | 更新 |
|---|---|---|---|
| 図鑑の基礎 | 種族値・タイプ・特性・技・持ち物 | Showdown のデータ＋チャンピオンズとの差分 | ゲームの更新時 |
| 使用率 | 採用率、ポケモンごとの技・持ち物・特性・性格、よく組まれる相方 | ゲーム内の画面（ミラーリングで撮って文字認識）。規約が許すサイトがあればそこから | 週1回ほど |
| 自分の構築 | 前シーズン2位の構築（固定）の6匹の型と、構築記事の立ち回り | 構築記事を読んで起こす | 構築を変えた時 |
| 試合の記録 | 選出・ターンごとの行動・受けたダメージ・勝敗・使ったトークン | 自動 | 毎試合 |
| 環境メモ | 「今はこの並びが多い」などの要約 | 記録の集計から Claude が書き直す | その日の終わり |

- 取ってきたデータには取得した日付を付ける。
- 構築が固定なので、よく当たる相手の並びごとの「選出と立ち回りの方針」を前もって用意する。
- 自分の記録は数が少なく自分のレート帯に偏る。50試合ほどまでは使用率を主にする。

### 置き場所

```
data/
  dex/            図鑑の基礎
  usage/          使用率（日付ごと）
  team/           自分の構築
  matches/        試合の記録（1試合1ファイル。例: 2026-10-21_001.json）
  meta_summary.md 環境メモ（Claude が読むのはこれだけ）
```

DB は使わない。1試合数 KB なので1000試合でも数 MB。細かい条件の集計を頻繁にしたく
なったら、JSON から SQLite に流し込む。1枚のドキュメントに書き足していく形は肥大化するので取らない。

## 8. 常駐と操作

- launchd（LaunchAgent）でログイン時に常駐。普段はミラーリングの窓があるかを見るだけ。
- 対戦画面を見つけた時だけ処理を始め、試合が終われば待機に戻る。助言の窓も自動で出し入れする。
- メニューバーに「一時停止」と「軽量モード（Haiku だけ・読み合いの局面だけ）」を置く。
  人狼の開発と同時に進める時は軽量モードにする（同じ Pro の枠を分け合うため）。
- 常駐化は最後。最初は手で起動する版で読み取りの精度を固める。

## 9. 作る順番

1. 調べる: チャンピオンズのダメージ計算・ステータスの仕組みと本編との違い、使用率の出どころと規約
2. 自分の構築と、図鑑・技のデータを用意する
3. ダメージ計算（記録で答え合わせできる形で）。ここまでで「確定数が分かる」だけでも対戦中に役立つ
4. 盤面の読み取り（ミラーリングの画面から盤面のテキストへ）。まず数枚のスクショで精度を見る
5. 試合の記録（助言の精度が低い段階でも、記録は先に溜め始める）
6. 探索エンジン
7. Claude の組み込み（型の推定の補助・振り返り・環境メモ）
8. 常駐化
