## 2026-10-22（初版の実装後）

### 実機が要るもの（優先）
- 画面の読み取りを実機のスクショで調整する。`npm run advise -- --keep` で撮りため、`npm run calibrate` で `config/layout.json` を直す。
  特に: 相手と自分の境目（oppSideMaxY）、HP バーの位置、結果画面の言葉、技選択の画面の判定。
- 画面の判定を文字だけに頼っている。技選択の画面のボタンなど、決まった絵があれば画像の一致を足す（DESIGN.md §3 の当初案）。
- 自分の選出3匹は助言の窓で手で押す形。選出確定の画面から読めるなら自動にする。
- 相手のアイコンの見分けの閾値（icons.ts の MATCH_THRESHOLD=18）は仮。覚えたアイコンが増えたら、取り違えが無いか確かめて直す。

### 探索エンジン
- 乱数を期待値で扱っているため、「乱1 88%」と「確1」を同じように扱う場面がある。KO の境目だけ2通りに分ける。
- 相手の控えのうち見ていない分は、使用率の高い順に仮置きしている。見せ合いの6匹から3匹の組み合わせで重みを付ける。
- 扱っていない要素: 急所、こんらん、壁、フィールド、トリックルーム、みがわり、アンコール・ちょうはつ、PP 切れ、こだわり以外の持ち物の多く（オボン等）。よく出るものから足す。
- 同速は自分が先として扱っている。半々にする。
- 選出の助言は1対1の殴り合いの合計なので、「カバルドンで起点を作ってルカリオで全抜き」のような積みの筋を低く見る。3対3の探索で選出を評価する。
- 自前のターン進行が Showdown（champions mod）とずれていないか、同じ盤面を両方で進めて比べるテストを足す。

### データ
- 使用率は Smogon（Showdown 上の対戦）。ゲーム内の使用率を画面から取る仕組みは未着手（DESIGN.md §7）。
- 型の推定は「配分・持ち物・技を独立に上位から組む」簡略版。Smogon の chaos には組み合わせの情報が無いので、記録が溜まったら自分の観測で補正する。

### 常駐
- メニューバーは作らず、助言の窓（web ページ）に一時停止・軽量モードを置いた。メニューバーが要るなら Swift で小さく作る。

## 2026-10-22（実機の1試合を再生して分かったこと）
- T1・T2（カバルドン 満タン近く vs リザードン）で「なまける 100%」と出た。満タン近くの回復技を推すのはおかしい。評価か、回復技の扱い（満タンで失敗）を見直す。
- 自分がメガシンカした後も「メガ＋」と出る。戦闘中の名前（メガルカリオ 等）でメガを検知できていないか、メガの表示名が違う。実機の表示を確かめる。
- 相手がメガ後の名前で行動した時（「相手のメガ○○の」）に種が読めず「?」になる。
- リザードンの型が Mega-Y 優先だが、実際はフレアドライブ（X 寄り）。見えた技から型を絞る処理が要る。
